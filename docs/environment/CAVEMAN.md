# Caveman Integration

## Installed state

Caveman skills are installed under `%USERPROFILE%\.agents\skills` and locked to recorded GitHub source hashes in `.skill-lock.json`. No standalone `caveman.exe`, `cavemem` command, or Caveman MCP server was discoverable on PATH during Phase 0.

Installed skill families include:

- `caveman` — compressed communication modes;
- `caveman-compress` — reversible memory-file compression;
- `caveman-learn` — token-sink analysis and consent-gated improvements;
- `caveman-discover` — workflow discovery;
- `caveman-evidence-review` — read-only evidence review;
- `caveman-manage` — experiment lifecycle controls;
- `caveman-optimize` — approved optimization evaluation;
- `caveman-review` — compressed code review;
- `caveman-setup` — Caveman Cloud setup;
- `caveman-stats` — usage reporting;
- supporting explore, build, migration, refactor, patch, verify, and crew skills.

## Fit

Caveman belongs in the communication and workflow layer. It can reduce repeated prompt/output cost and improve task discipline. It does not replace source inspection, tests, documentation retrieval, or code intelligence.

## Cavemem status

Cavemem `0.2.1` was installed and benchmarked in Phase 5, then removed. Cross-session recall worked; project isolation failed because search had no project namespace/filter. No Cavemem command or MCP endpoint remains.

Do not reinstall unless a newer version demonstrably fixes project isolation and update precedence. Use project docs and decision records for durable knowledge.

## Safety

Do not reinstall or replace the current Caveman installation. Do not store secrets or raw credentials in memory. Keep compressed backups outside tracked source. Treat Caveman evidence and recalled memory as advisory until verified against current files.
